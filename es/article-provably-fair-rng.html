Provably Fair y RNG: cómo verificar el resultado de un juego

Después de una racha fulera aparece el “esto está arreglado”. Provably Fair permite revisar una ronda con datos, no con bronca ni corazonadas. Veamos qué prueba de verdad.

En pocas palabras: el RNG genera el resultado; Provably Fair deja una prueba de que los datos comprometidos no se cambiaron después de la ronda. Que cierre la cuenta no significa que vaya a pegar un premio.

RNG y Provably Fair no son lo mismo

El RNG genera valores aleatorios o pseudoaleatorios. Decide dónde cae la bola de Plinko, dónde están las minas o qué multiplicador larga Limbo.

Provably Fair es un sistema de compromiso y revelación. El servidor publica primero el hash de un secreto, combina ese secreto con datos del jugador y un contador, y más tarde lo revela para que cualquiera repita la cuenta.

En criollo: el RNG saca el resultado. Provably Fair deja un “ticket” criptográfico para comprobar que no lo cocinaron después de que entró la apuesta.

Las cuatro piezas del sistema

Server seedCadena secreta del servidor; antes de rotarla normalmente solo se ve su hash.
Client seedValor aportado por el usuario o el navegador.
NonceContador de rondas: 0, 1, 2…
HashHuella digital, muchas veces SHA-256.

Qué pasa en una ronda

El servidor se comprometePublica el hash antes de jugar: el secreto queda oculto, pero sellado.
Se suman client seed y nonceEl orden exacto cambia según la implementación.
El número se convierte en resultadoUna regla lo mapea a una casilla de Plinko, tablero de Mines o multiplicador de Limbo.
Se revela el server seedDespués se puede recalcular la ronda vieja.
HMAC/SHA-256 (server seed, client seed + nonce) → número → regla del juego → resultado

Es un esquema general, no una fórmula universal. Un verificador de otro Plinko no sirve automáticamente para Mines.

Cómo verificar una ronda

En Fairness o Verify buscá el server seed viejo ya revelado, su hash anterior, el client seed, el nonce y el algoritmo exacto.

ControlQué debe coincidirQué demuestra
CompromisoEl hash del seed revelado coincide con el anteriorEl secreto no se cambió después
CálculoEl verifier devuelve el mismo valorLos seeds y el nonce reproducen la ronda
MapeoEl valor cae en la misma casilla o multiplicadorSe aplicó la regla publicada
Bandera roja: el logo Provably Fair no alcanza. Sin seeds viejos, hash original y fórmula precisa no hay verificación independiente.

Verificable no significa ganable

Provably Fair puede demostrar que un resultado no fue reemplazado. No promete RTP alto, pagos generosos ni una racha copada. Un algoritmo transparente puede conservar ventaja matemática para la casa.

Que ayer Plinko haya pegado lindo no deja “cargada” la próxima bola. Que Mines te haya reventado el saldo en tres rondas tampoco prueba manipulación: el azar arma rachas que parecen guionadas.

Qué prueba y qué no

Sí puede probarQue el seed revelado coincide con el hash previo.
Sí puede probarQue la fórmula publicada reproduce esa ronda.
No puede probarQue el RTP sea alto o que tu saldo aguante.
No puede probarLa licencia, los retiros o toda la conducta del operador.

Preguntas frecuentes

¿El server hash permite adivinar la próxima ronda?

No en una implementación sólida. El server seed sigue oculto y recuperarlo desde SHA-256 es impracticable.

Si coincide, ¿toda la plataforma es confiable?

Verificaste un cálculo. No auditaste licencia, retiros, RTP ni el resto del operador.

¿Cambiar el client seed corta la mala racha?

No. Cambia un dato de entrada, no pone las probabilidades a tu favor.

¿Se puede manipular un RNG?

Una implementación débil u opaca puede tener fallas. Importan la documentación, las pruebas independientes y un cálculo reproducible.
